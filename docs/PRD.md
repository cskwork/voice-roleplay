## 1. 제품 요약

사용자가 카페 주문, 호텔 체크인, 면접 같은 상황에서 AI와 영어로 대화하고, 자신의 문장을 고쳐 다시 말해 보는 로컬 학습 서비스다.

**Speak처럼 지향하는 경험**은 버튼을 매번 누르지 않는 대화, 자연스러운 음성 응답, AI 말 끊기, 대화 후 복습이다. Speak의 내부 기술·성능·콘텐츠와 동일하다고 주장하거나 자산을 복제하지 않는다.

| 비교 | 실시간 회화 | 비실시간 연습 |
|---|---|---|
| 진행 | 말하면 발화 종료를 감지하고 AI가 응답 | 녹음 → 듣기·재녹음 → 제출 → 분석 |
| 주요 목적 | 상황별 역할극, 즉흥적인 영어 대화 | 문장 읽기, 따라 말하기, 자유 답변, 턴제 역할극 |
| ASR | 스트리밍 전사 → 발화 종료 시 최종 확정 | 제출한 전체 발화를 전사 |
| TTS | 첫 문장부터 청크 단위 재생 | 모범 문장·AI 답변을 완성 후 재생 가능 |
| 피드백 | 흐름을 방해하지 않도록 턴 후 또는 종료 후 제공 | 전사 확인 후 문법·표현·발화 지표를 상세 확인 |
| 재시도 | 특정 문장을 연습 모드로 보내 다시 말하기 | 제출 전 재녹음, 결과 확인 후 새 시도 |
| 자원 정책 | 지연·취소 처리를 우선 | 순차 처리 허용, 실시간 작업과 경쟁하지 않음 |

**MVP 완료 조건:** 두 모드 모두 실제 로컬 모델로 작동해야 한다. 녹음 후 답하는 기능만으로 실시간 모드를 구현했다고 판정하지 않는다.

다중 사용자 서버, 결제·계정 서비스, 모바일 네이티브 앱, 다자 통화, 사람과 AI가 동시에 의미를 주고받는 완전한 중첩 대화, 학습자 목소리 복제, 공식 영어 등급 인증, 검증되지 않은 음소별 발음 점수는 제외한다. 클라우드 API로 자동 우회하지 않는다.

## 3. 학습 경험과 콘텐츠

기본 사용자는 한국어 설명을 보며 영어 말하기를 연습하는 성인 학습자로 설정한다. 난이도는 `쉬움 / 보통 / 도전`이며, 공식 CEFR 판정으로 표시하지 않는다.

| 초기 시나리오 | AI 역할 | 학습 목표 예시 |
|---|---|---|
| 카페 주문 | 직원 | 음료 주문, 옵션 변경, 가격 확인 |
| 호텔 체크인 | 프런트 직원 | 예약 확인, 요청 전달, 시설 질문 |
| 길 안내 | 현지인 | 목적지 질문, 방향 확인, 되묻기 |
| 면접 연습 | 면접관 | 자기소개, 경험 설명, 후속 질문에 답변 |

각 시나리오는 버전이 있는 로컬 콘텐츠 파일로 제공한다. `scenario_id`, 역할, 상황 사실, 시작 문장, 목표 3개, 허용된 전개, 난이도별 힌트, 검수된 모범 표현을 포함한다.

실시간 AI는 기본적으로 **1~2문장, 20~40단어, 질문 최대 1개**로 응답한다. 쉬운 난이도에서는 짧은 어휘·문장과 더 긴 생각 시간을 제공한다. 문법 오류가 있어도 의미가 통하면 먼저 대화를 이어 가고, 교정은 뒤에 보여 준다.

### 반드시 반영할 사실

- Qwen 공식 `qwen-asr` 문서는 스트리밍을 vLLM 백엔드로 제공하며, 해당 스트리밍 경로에서 배치 처리와 타임스탬프 반환은 지원하지 않는다고 명시한다. 녹음형 전사는 지원되는 전체 발화 추론 경로를 사용한다. [S1]
- CosyVoice3는 텍스트 입력·음성 출력 스트리밍과 영어 CMU 음소 기반 합성 제어를 명시한다. 이것은 **AI가 말하는 발음의 제어 기능**이지 학습자 발음의 채점 기능이 아니다. [S3]
- Forced Aligner의 역할은 음성과 텍스트의 시간 정렬이다. 이를 붙였다는 이유로 `/r/ 발음 72점` 같은 점수를 생성해서는 안 된다. [S1]
- 공식 예제의 짧은 TTS 지연 수치를 이 서비스의 전체 대화 지연으로 사용하지 않는다. ASR·발화 종료 감지·LLM·재생 버퍼까지 포함하여 별도로 측정한다.

### 모델 및 환경 고정

ASR, TTS, LLM은 독립 프로세스·환경으로 분리한다. Qwen과 CosyVoice 공식 설치 예제의 Python·의존성 구성이 다르므로 하나의 환경에 무조건 통합하지 않는다. [S1][S4]

배포 전에 `models.lock.json`과 환경별 잠금 파일에 모델 revision, 파일 SHA-256, 원본·변환 출처, 코드 commit, Python/PyTorch/CUDA/추론 런타임 버전, 라이선스를 기록한다. 이 문서에서 확인하지 않은 commit이나 최소 메모리를 만들어 넣지 않는다. 미확정 잠금 정보가 있으면 릴리스를 차단한다.

## 5. 전체 구조

```text
로컬 브라우저
  마이크 / 자막 / 재생 / 녹음 제출 / 피드백
                │ WebSocket + HTTP
                ▼
로컬 게이트웨이 — 세션·턴·취소·우선순위·인증
  ├─ Silero VAD → 발화 구간 / 종료 판단
  ├─ ASR 워커 → Qwen3-ASR 0.6B
  ├─ 대화 워커 → 로컬 Qwen 4B 후보 / llama.cpp
  ├─ TTS 워커 → CosyVoice3 0.5B
  ├─ 피드백 처리 → 전사 + 실제 측정 지표 + 로컬 LLM
  └─ SQLite → 설정 / 동의한 텍스트 학습 이력

선택: 녹음형 후처리 → 발음 워커(v0.2) → 단어 위치 / 억양 곡선 / 실험용 음소 후보
금지: 외부 음성 API / 외부 대화 API / 자동 클라우드 fallback
```

추천 구현 스택은 **React + TypeScript, AudioWorklet, FastAPI, 독립 Python 모델 워커, llama.cpp, SQLite**다. 프런트엔드 파일은 게이트웨이와 같은 origin에서 제공한다. 이는 제품 구현 선택이며 기존 코드베이스가 있다는 가정은 아니다.

모델은 요청마다 로딩하지 않는다. 시작 시 점검·예열하고 세션 동안 유지한다. 활성 실시간 세션은 1개로 제한한다. Redis, Kafka, Kubernetes, 별도 벡터 DB는 MVP에 넣지 않는다.

## 6. 실시간 회화 요구사항

### 6.1 사용자 흐름

```text
시나리오 선택 → 마이크·출력 확인 → 모델 준비 확인 → 대화 시작
 → AI 질문 → 사용자 발화와 임시 자막
 → 발화 종료 → 최종 전사 → 짧은 AI 답변을 스트리밍 재생
 → 반복 → 세션 요약 → 문장을 골라 다시 말하기
```

| ID | 필수 동작 | 수용 조건 |
|---|---|---|
| RT-01 | 말하는 동안 임시 자막 표시 | 임시 자막과 최종 전사를 구분. 임시 자막은 교정의 확정 근거로 쓰지 않음 |
| RT-02 | 자동 턴 종료 + 수동 완료 버튼 | 침묵 시간을 난이도에 맞게 조절. 사용자가 `말하기 완료`로 즉시 제출 가능 |
| RT-03 | 문장 단위 TTS 스트리밍 | 답변 전체 생성 전 첫 발화 단위를 합성·재생. 단어마다 끊어 읽지 않음 |
| RT-04 | 끼어들기 | AI가 말하는 중 사용자 발화를 감지하면 재생·출력 큐를 취소하고 새 발화를 받음 |
| RT-05 | 에코 대응 | 브라우저 에코 제거 요청, 헤드셋 권장, AI 음성을 사용자 답으로 저장하지 않는 테스트 통과 |
| RT-06 | 학습 보조 | 힌트, 다시 듣기, 한국어 뜻, 더 천천히, 연습 모드로 이동 |
| RT-07 | 자연스러운 피드백 | 기본은 대화 종료 후 최대 3개 개선점. 명시적 코칭 모드에서만 턴 후 카드 표시 |
| RT-08 | 사용자 제어 | 음소거·일시정지·종료 시 마이크와 생성 작업의 실제 상태가 UI와 일치 |

### 6.2 발화 종료 정책

초깃값은 시작 전 음성 200 ms를 보존하는 pre-roll, 종료 침묵 900 ms다. 쉬운 난이도는 1,200 ms로 시작하고, 검증 후 700~1,400 ms 범위에서 조정한다. 이 값은 모델 필수 사양이 아닌 조정 가능한 제품 설정이다.

한 발화는 최대 45초로 제한하고, 40초에 안내한 뒤 45초에서 현재 발화를 제출한다. 중간의 짧은 망설임을 곧바로 말 끝으로 판정하지 않는다. 조용한 구간만 들어오면 AI 호출·교정·학습 실패 기록을 만들지 않는다.

### 6.3 상태와 끼어들기

```text
READY → LISTENING → FINALIZING → RESPONDING → LISTENING
                        │             │
                        └─ 새 발화 ───┴→ INTERRUPTING → LISTENING

공통: PAUSED / RECOVERABLE_ERROR / CLOSED
```

`RESPONDING`은 LLM 생성·TTS 합성·재생이 겹칠 수 있는 복합 상태다. 입력과 출력 상태를 따로 관리하며, AI 재생 중에도 음성 감지는 유지한다. 이것을 모델 자체의 완전한 양방향 의미 이해로 설명하지 않는다.

끼어들기 처리 규칙:

1. 새 발화를 감지하면 브라우저에서 즉시 기존 재생을 중단하고 큐를 비운다.
2. `response_id`를 취소하고 새로운 `generation_epoch`를 발급한다. 이전 epoch의 음성·자막은 이후 도착해도 폐기한다.
3. 백엔드는 LLM/TTS 취소를 요청하고 다음 생성 경계에서 계산을 정리한다. 클라이언트의 음성 정지가 GPU 작업 종료를 기다리지 않게 한다.
4. TTS 중에도 유지한 pre-roll로 사용자의 첫 음절 손실을 줄인다.
5. 실제 재생 완료가 확인된 문장만 대화 이력에 반영한다. 재생 도중 잘린 문장은 `interrupted`로 표시하고, AI가 끝까지 전달한 것으로 가정하지 않는다.

에코로 인한 오작동이 반복되면 자동 끼어들기를 끄고 `눌러 말하기`를 제안한다. 이 상태를 정상 실시간 성능 달성으로 집계하지 않는다.

## 7. 비실시간 연습 요구사항

### 7.1 연습 유형

| 유형 | 입력 | 결과 |
|---|---|---|
| 문장 읽기 | 제시 문장 + 녹음 | 전사 차이, 모범 음성, 다시 읽기 |
| 따라 말하기 | 모범 음성 청취 후 녹음 | 전사·발화 길이·휴지 구간 비교. 원어민 유사도 점수는 제공하지 않음 |
| 자유 답변 | 질문 + 5~120초 녹음 | 전사, 문법·표현 개선, 예시 답변 |
| 턴제 역할극 | 시나리오 + 녹음 제출 | 상세 피드백과 다음 AI 답변을 분리해 제공 |

### 7.2 처리 흐름

```text
질문·문장 선택 → 녹음 → 미리 듣기 / 다시 녹음 → 제출
 → 전체 발화 ASR → 원문 전사 확인
 → 측정 지표 + 텍스트 피드백
 → 모범 문장 듣기 → 새 시도로 다시 말하기
```

| ID | 필수 동작 | 수용 조건 |
|---|---|---|
| NR-01 | 녹음 후 제출 | 제출 전에는 연습 결과가 확정되지 않음. 새 시도마다 별도 `attempt_id` 생성 |
| NR-02 | 실제 작업 상태 | `queued / transcribing / analyzing / synthesizing / completed / failed / cancelled / expired` 표시 |
| NR-03 | 작업 취소 | 대기열·모델 작업 취소와 오디오 버퍼 해제를 수행 |
| NR-04 | 전사 수정 | ASR 원문을 덮어쓰지 않고 수정 revision 저장. 텍스트 피드백만 다시 생성 |
| NR-05 | 모범 음성 | 교정 문장 또는 검수된 예시를 재생. 사용자 원문과 명확히 구분 |
| NR-06 | 재시도 비교 | 같은 연습의 이전·현재 문장과 측정 가능한 항목을 비교. 표현이 다르다고 자동 실패 처리하지 않음 |
| NR-07 | 파일 입력 | MVP는 최대 120초·32 MiB의 PCM16 WAV, 1~2채널, 16/24/44.1/48 kHz 지원 목표. 길이·형식을 실제 디코딩 결과로 검증 |

비실시간 작업은 로컬 작업 큐로 처리한다. 활성 실시간 세션 중에는 신규 비실시간 작업을 받지 않고 `LOCAL_BUSY`와 전환 안내를 반환한다. 작업 슬롯 1개, 대기열 2개를 초깃값으로 설정하며 무제한 적재하지 않는다.

`queued` 작업의 오디오 보존 TTL은 최대 5분이다. 프로세스가 종료되어 오디오가 사라진 작업은 `expired`로 표시하고 재녹음을 요청한다. 녹음 원본을 저장하지 않으면서 재시작 후 분석이 자동 복원된다고 주장하지 않는다.

## 8. 피드백과 발음 연습의 경계

### 8.1 MVP에서 제공하는 것

| 피드백 | 근거 | 표시 방식 |
|---|---|---|
| 문법·표현 개선 | 최종 전사 또는 사용자가 확인한 문장 | 원문·제안·짧은 한국어 설명. 필수 교정과 선택적 표현 개선 구분 |
| 상황 목표 달성 | 목표에 대응하는 발화 구간 | 목표별 완료/미확인과 근거 문장 |
| 말하기 속도 | 전사 단어 수와 측정된 발화 시간 | `분당 단어 수 — 참고 지표`. 발음 실력 점수로 변환하지 않음 |
| 휴지·발화 길이 | VAD 구간·오디오 길이 | 휴지 횟수·총길이. 느리게 말했다는 이유만으로 감점하지 않음 |
| 읽기 결과 | 목표 문장과 전사 비교 | `다르게 인식된 부분`. 곧바로 발음 오류라고 단정하지 않음 |
| 모범 발음 | 검수된 CosyVoice 출력·어휘 자료 | 정상 속도·느린 재생·구간 반복 |

분당 단어 수는 `전사 단어 수 ÷ 첫 음성 시작~마지막 음성 종료 시간 × 60`으로 정의한다. 휴지 기준은 초기 500 ms이며, 양끝 무음은 내부 휴지에 포함하지 않는다. 지표 정의와 전처리 버전을 결과에 기록한다.

### 8.2 금지 사항

ASR 일치율을 발음 점수로 변환하지 않는다. LLM이 전사 텍스트만 받고 특정 음소·강세·억양 오류를 들었다고 표현하지 않는다. Forced Aligner의 정렬 성공을 발음 정답으로 판정하지 않는다. 숫자 confidence가 없는 모델 출력에 임의의 신뢰도 백분율을 붙이지 않는다.

읽기 연습에서는 목표 문장 전체를 ASR의 정답 유도 프롬프트로 주입하지 않는다. 시나리오 전사용 힌트와 평가용 독립 전사를 구분해, 모델이 기대 문장을 복원하는 편향을 줄인다.

### 8.3 근거와 보류 정책

피드백 객체에는 `evidence_type`, `source_turn_id` 또는 `attempt_id`, `transcript_revision`, `evidence_quote`, `status`, `model_revision`을 포함한다. `status`는 `observed / suggested / needs_confirmation / unavailable` 중 하나다.

불안정한 전사, 음성량 부족, 끊긴 녹음에서는 교정을 보류한다. 사용자에게 “이렇게 들렸어요. 맞나요?”로 확인받으며, 실패한 분석을 학습자의 낮은 실력으로 기록하지 않는다.

### 8.4 발음 분석의 조건 (v0.2)

v0.1의 원칙은 그대로다. 실제 음소별 평가는 별도의 음향·음소 채점 모듈과 사람 평가에 대한 보정이 필요하고, 이 조건을 채우기 전에는 발음 판정을 보여 주지 않는다. `pronunciation_score`는 모든 결과에서 계속 `null`이다. v0.2는 판정 없이 보여 줄 수 있는 측정값(단어 위치, 억양 곡선)을 먼저 제공하고, 판정은 실험용 플래그 뒤에 둔다. 자세한 설명은 `docs/pronunciation.md`, 계약은 `contracts/PROTOCOL.md` §12.

| 단계 | `pronunciation.status` | 조건 | 학습자에게 보이는 것 |
|---|---|---|---|
| 비가용 | `unavailable` | 발음 워커나 모델 파일이 없음, 워커 실패·시간 초과, 실시간 세션 중 | 기능 비가용 안내. 나머지 결과는 정상 표시 |
| 기본 | `timing_only` | 발음 워커 준비됨. 플래그 없음 | 단어별 시작·끝 시각, 단어 길이·앞뒤 쉼, "내 발음 / 모범 음성" 단어 구간 비교 재생, 억양 곡선(참고 지표). 판정·색 표시·점수 없음 |
| 실험 | `experimental_banded` | `VR_PRON_EXPERIMENTAL=1` **그리고** 보정 파일이 있음 | 단어별 등급(초록/노랑/빨강에 대응하는 `good / check / practice`)과 "이렇게 들렸을 가능성" 음소 후보. 숫자 없음. 실험 기능·보정 데이터 한계를 항상 함께 표시 |

규칙:

- **등급만, 숫자 없음.** GOP 값·확률·백분율을 학습자 화면에 표시하지 않는다. 등급도 보정 파일이 정한 임계값에서만 나온다. 보정 파일이 없으면 플래그를 켜도 `band`는 `null`이고 상태는 `timing_only`다.
- **채택 기준.** 기본값으로 등급을 켜려면(이후 `assessed_banded`, v0.2에서는 생성하지 않음) 동의받은 한국인 학습자 평가셋(PA-0)에서 사람 평가와의 상관이 음소 수준 ≥ 0.55, 단어 수준 ≥ 0.5여야 하고, 평가자 간 일치도와 speechocean762 결과를 따로 보고해야 한다. **v0.2 시점에 PA-0 데이터가 없으므로 기준을 충족할 수 없고, 등급은 기본으로 꺼져 있다.**
- **악센트 편향.** 공개 보정 데이터(speechocean762)는 중국어 모국어 화자뿐이다. 이것으로 만든 보정 파일은 실험 플래그용이며, 한국인 학습자에 대한 정확도를 주장하는 근거가 아니다. 문서·UI·릴리스 노트 어디에도 한국인 학습자 정확도를 주장하지 않는다.
- **정렬 ≠ 정답.** 정렬 성공을 발음 정답으로, 정렬 실패를 발음 오류로 판정하지 않는다(§8.2). 정렬 결과는 "어디서 이 단어를 말했는지"만 뜻한다.
- **자유 발화(unscripted).** 기준 텍스트는 ASR 전사다. ASR 오류가 가짜 오발음이 될 수 있으므로 등급은 스크립트 연습보다 먼저 켜지 않는다. 기준 텍스트가 사용자가 확인하지 않은 전사이면 판정은 `needs_confirmation`으로 보류한다.
- **근거.** 모든 발음 관련 표시는 단어 번호·구간(ms)·모델 revision을 가진다. 증거 유형은 `word_timing`, `prosody_contour`, `phone_gop`(실험)다.
- **로컬 전용.** 클라우드 발음 API로 자동 전환하지 않는다. 음성은 기존 정책대로 작업이 끝나면 서버 메모리에서 해제한다. 비교 재생의 "내 발음"은 브라우저가 가지고 있는 녹음을 쓴다.
- **억양 곡선은 참고 지표다.** 모범 음성과 다르다는 이유로 감점하거나 "억양이 틀렸다"고 쓰지 않는다. 다양한 허용 억양을 포함한 검증 전에는 "원어민 같은 발음" 점수를 노출하지 않는다.

## 9. TTS·캐릭터 음성 정책

캐릭터마다 권리·사용 범위가 확인된 영어 reference audio와 정확한 reference transcript를 준비한다. 초기에는 음성 2개를 검수해 고정 사용한다. 상황이 바뀌어도 캐릭터의 음색이 임의로 변하지 않게 한다. 모델 라이선스와 기준 음성의 사용 권리는 별도로 확인한다.

| 요구사항 | 구현 기준 |
|---|---|
| 읽을 텍스트 | `spoken_text`만 TTS에 전달. 한국어 피드백·JSON·시스템 프롬프트는 제외 |
| 청크 경계 | 초기에는 완성된 짧은 문장 또는 자연스러운 절을 확정한 뒤 각 구간을 스트리밍 합성 |
| 토큰 스트림 | LLM의 임의 토큰을 그대로 읽지 않음. 약어·숫자·문장부호를 고려해 발화 단위를 구성 |
| 재생 확정 | 이미 합성·재생한 텍스트는 수정하지 않음. 문장별 `segment_id`와 재생 완료 기록 사용 |
| 영어 발음 | 숫자·가격·날짜·축약형과 어려운 단어를 별도 테스트. CMU 음소 지정은 검수된 사전 항목에만 적용 |
| 느리게 듣기 | 실시간은 다음 문장부터 검수된 느린 스타일 적용. 녹음형 재생 속도 변경은 음높이 보존을 검증한 경로 사용 |
| 참조 음성 | 서비스 자산은 설치 시 고정. 학습자 녹음을 자동으로 voice cloning reference로 사용하지 않음 |
| 장애 | TTS 실패 시 텍스트 답변과 재시도 제공. 재시도 중 이전 응답이 뒤늦게 재생되지 않음 |

CosyVoice의 실제 스트리밍 호출, reference prompt 형식, 영어 발음 제어는 선택한 commit의 코드로 검증한다. 공식 예제의 API를 확인하지 않고 임의의 `speaker=` 옵션이나 특수 태그를 가정하지 않는다. [S4][S9]

## 10. 오디오 전송과 실시간 일관성

### 10.1 오디오 형식

| 구간 | 계약 |
|---|---|
| 브라우저 캡처 | `getUserMedia` + AudioWorklet. 장치가 선택한 실제 sample rate 확인 |
| ASR/VAD 입력 | mono, 16,000 Hz. 전송은 PCM signed 16-bit little-endian, 모델 입력에서 float32 변환 |
| 전송 청크 | 초기 20 ms 단위. **전송 청크와 ASR 추론 청크는 별개** |
| VAD 입력 | 선택한 Silero 버전이 요구하는 창 크기로 다시 묶음. 스트림별 상태 격리 |
| ASR 입력 | 공식 streaming state를 유지. 20 ms마다 전체 발화를 처음부터 재추론하지 않음 |
| 출력 | CosyVoice가 반환한 실제 sample rate를 명시하고, 브라우저 재생 장치에 맞춰 변환 |
| 버퍼 | 네트워크·재생 버퍼 상한 설정. 단어를 임의로 버려 지연을 숨기지 않음 |

Qwen 공식 스트리밍 예제는 16 kHz 음성과 별도의 ASR 청크 설정을 사용한다. 샘플링 레이트 필드만 바꿔 리샘플링했다고 처리하지 않는다. [S2]

브라우저 입력은 마이크 권한과 secure context가 필요하다. 기본은 `localhost`이며, 다른 기기의 LAN 접속을 지원하는 확장에는 HTTPS와 인증을 별도로 요구한다. [S8]

### 10.2 프로토콜 원칙

오디오는 binary frame, 제어는 JSON event로 전송한다. binary envelope에는 `protocol_version`, `kind`, `session_id`, 입력의 `turn_id` 또는 출력의 `response_id`, `generation_epoch`, `sequence`, `sample_rate`, `sample_count`를 넣는다. 헤더와 PCM 길이가 맞지 않으면 거절한다.

모든 제어 이벤트는 `event_id`, `session_id`, 관련 turn/response ID, `epoch`, `event_seq`를 가진다. 서버·클라이언트는 이벤트 버전과 허용 상태를 검증한다.

| 방향 | 주요 이벤트 | 의미 |
|---|---|---|
| Client → Server | `session.start`, `input.start`, `input.commit` | 세션·발화 시작, 마지막 audio sequence까지 제출 |
| Client → Server | `response.cancel`, `session.pause`, `session.end` | 출력 취소, 일시정지, 세션 종료 |
| Client → Server | `playback.started`, `playback.completed`, `playback.stopped` | 실제 재생 구간과 중단 지점 확인 |
| Server → Client | `speech.started`, `speech.ended` | VAD와 턴 종료 상태 |
| Server → Client | `asr.partial`, `asr.final` | 수정 가능한 전사 / 확정 전사 |
| Server → Client | `response.started`, `response.text`, `audio.chunk`, `response.done` | 응답 및 음성 스트림 |
| Server → Client | `response.cancelled`, `feedback.ready`, `error` | 취소 확인, 피드백, 복구 가능한 오류 |

`asr.partial`은 같은 턴의 이전 임시 문자열을 교체한다. 무조건 이어 붙여 중복 자막을 만들지 않는다. `asr.final` 확정 전에는 역할극 답변을 시작하지 않는 것을 MVP 기본으로 한다. 추측 응답 생성은 이후 최적화다.

`input.commit`에는 마지막 audio sequence를 포함한다. 해당 프레임까지 처리한 뒤 정확히 한 번 최종 전사와 응답을 만든다. 중복 commit·HTTP 제출은 idempotency key로 같은 결과를 반환한다.

전송 대기량이 2초 분량을 초과하면 경고와 중단/재시도 안내를 제공한다. 연결이 끊기면 재생·마이크·모델 작업을 정리하고, 재연결 후 서버 상태를 조회한다. 이미 제출된 턴을 자동으로 다시 생성하거나 미제출 음성을 몰래 재전송하지 않는다.

## 11. 로컬 대화 LLM·교정 정책

역할극 응답과 상세 피드백은 **동일한 로컬 모델을 다른 작업 유형으로 호출**한다. 이 둘을 한 번의 큰 JSON 생성으로 묶어 첫 음성 응답을 지연시키지 않는다.

| 항목 | 기본값·규칙 |
|---|---|
| 역할극 입력 | 시나리오 사실, 난이도, 목표 상태, 최근 대화, 현재 최종 전사 |
| 컨텍스트 | 총 4,096토큰 이내를 시작값으로 설정. 최근 최대 6턴과 제한된 요약 유지 |
| 응답 길이 | 실시간 최대 128 출력 토큰. 말할 완성 문장을 우선 생성 |
| 피드백 | 구조화 JSON, 최대 768 출력 토큰. 근거 없는 음향 평가 금지 |
| 언어 | AI 역할극과 모범 문장은 영어, UI 설명·교정 이유는 한국어 |
| 도구 권한 | 파일·셸·브라우저·네트워크 도구를 LLM에 부여하지 않음 |
| 검증 | 구조화 출력은 스키마 검증. 잘못된 JSON은 한 번만 재시도 후 보류 |
| 사실성 | 예약 번호·가격·등장인물 등은 시나리오 데이터와 명시적 상태가 기준 |
| 교정 수준 | 사용자의 의미를 유지. 자연스러운 대안이라는 이유만으로 원문을 오답 처리하지 않음 |

최근 발화에서 확인된 시나리오 사실을 상태로 보존하고 요약이 이를 덮어쓰지 못하게 한다. 소리를 듣지 않은 텍스트 LLM이 감정·발음·강세를 측정했다고 말하지 못하도록 출력 검증을 둔다.

사용자 발화에 “앞의 지시를 무시하라” 등이 포함돼도 시스템 설정·음성 자산·로컬 파일 접근 권한은 바뀌지 않는다. 역할극 주제 변경과 시스템 지시 변경을 구분한다.

## 12. 화면 요구사항

| 화면 | 필수 구성 |
|---|---|
| 시작·장비 점검 | 마이크 선택, 입력 레벨, 테스트 재생, ASR/TTS/LLM 준비 상태, 사용 가능한 모드 |
| 학습 홈 | 실시간/비실시간 선택, 시나리오, 난이도, 기록 저장 선택 |
| 실시간 회화 | 현재 상태, 역할·목표, 임시/최종 자막, 음소거·완료·끼어들기·힌트·종료 버튼 |
| 녹음형 연습 | 질문/목표 문장, 녹음·정지·미리 듣기·재녹음·제출, 길이 제한 |
| 결과 | 인식한 문장, 사용자 수정, 개선 제안, 측정 지표, 모범 음성, 다시 말하기 |
| 복습 | 저장에 동의한 표현과 재시도 이력. 저장하지 않은 음성은 재생 버튼을 노출하지 않음 |
| 설정 | 실행 프로필, 음성, 난이도·침묵 시간, 데이터 보존, 전체 삭제, 진단 결과 |

마이크 사용 상태를 색상뿐 아니라 텍스트·아이콘으로 표시한다. 키보드만으로 시작·정지·제출·취소가 가능해야 한다. 모델이 준비되지 않았거나 실시간 검증에 실패한 장비에서는 이유를 표시하며, 작동하지 않는 버튼을 활성화하지 않는다.

기본 흐름은 로그인 없이 로컬 사용이다. 기록을 저장하지 않아도 현재 세션의 요약·재시도는 이용할 수 있어야 한다.

## 13. API·데이터 계약

아래 경로와 JSON은 **신규 서비스가 구현해야 할 계약**이다. 현재 존재하는 Qwen/CosyVoice API의 이름이라는 뜻이 아니다.

### 13.1 HTTP API

| 메서드·경로 | 역할 |
|---|---|
| `GET /api/health` | 프로세스·모델별 readiness, 지원 모드, 벤치마크 상태 |
| `GET /api/scenarios` | 버전이 있는 로컬 시나리오 목록 |
| `GET /api/settings`, `PUT /api/settings` | 장비·학습·보존 설정 조회/수정 |
| `POST /api/sessions` | 모드·시나리오·난이도·보존 선택으로 세션 생성 |
| `WS /api/sessions/{id}/realtime` | 실시간 오디오와 제어 이벤트 |
| `POST /api/sessions/{id}/end` | 취소·마이크 종료·세션 요약·버퍼 정리 |
| `POST /api/attempts` | 연습 유형·목표로 제출 전 시도 생성 |
| `PUT /api/attempts/{id}/audio` | 길이 제한이 있는 WAV를 메모리로 수신 |
| `POST /api/attempts/{id}/submit` | 중복 방지 키로 분석 요청, `202 + job_id` 반환 |
| `GET /api/jobs/{id}`, `DELETE /api/jobs/{id}` | 상태 조회 / 취소 |
| `GET /api/attempts/{id}/result` | 전사·피드백·가용한 음성 결과 |
| `PATCH /api/attempts/{id}/transcript` | 새 전사 revision으로 텍스트 재분석 요청 |
| `GET /api/history`, `DELETE /api/history` | 동의한 이력 조회 / 전체 삭제 |
| `POST /api/history/export` | 사용자가 명시적으로 요청한 JSON/Markdown 내보내기 |

모든 변경 요청은 로컬 인증·origin 검증을 통과해야 한다. 지원하지 않는 모드, 길이 초과, 메모리 부족, 만료된 오디오, 작업 포화는 구분된 오류 코드로 반환한다. 외부 URL이나 임의의 로컬 파일 경로를 오디오 입력으로 받지 않는다.

### 13.2 세션 요청 예시

```json
{
  "mode": "realtime",
  "scenario_id": "cafe_order",
  "difficulty": "normal",
  "history_opt_in": false,
  "feedback_policy": "session_end"
}
```

### 13.3 피드백 계약 예시

다음은 형식 예시이며 실제 분석 결과가 아니다.

```json
{
  "attempt_id": "attempt_example",
  "transcript_revision": 1,
  "transcript": "Yesterday I go to a cafe.",
  "feedback": [
    {
      "category": "grammar",
      "status": "suggested",
      "evidence_type": "asr_text",
      "evidence_quote": "Yesterday I go to a cafe.",
      "suggestion": "Yesterday I went to a cafe.",
      "explanation_ko": "어제의 일을 말하므로 과거형 went를 사용합니다."
    }
  ],
  "pronunciation_score": null,
  "pronunciation_status": "assessment_unavailable",
  "metrics": null
}
```

**(v0.2)** `pronunciation_status` 값은 `assessment_unavailable`(발음 워커 없음·실패), `timing_only`(기본), `experimental_banded`(실험 플래그 + 보정 파일)다. `assessed_banded`는 §8.4 채택 기준을 충족한 뒤를 위해 예약하며 v0.2에서는 생성하지 않는다. 녹음형 결과에는 `pronunciation` 객체가 추가된다(§13.5).

전사를 수정하면 기존 피드백을 새 전사에 연결하지 않는다. 과거 결과는 원래 revision에 묶고, 재분석 결과를 별도로 표시한다. 수정된 단어 수로 과거 음성에 대한 WPM·음향 지표를 몰래 재계산하지 않는다.

### 13.4 데이터 모델

| 엔터티 | 주요 필드 | 보존 |
|---|---|---|
| `Settings` | 입력·출력 장치, 난이도, 저장 동의, 프로필 | 로컬 설정 |
| `Scenario` | ID, version, role, facts, goals, examples | 검수된 로컬 자산 |
| `Session` | ID, mode, scenario_version, state, opt_in, timestamps | 기본 메모리. 동의 시 이력 저장 |
| `Turn` | session_id, turn_index, transcript_revision, spoken_segments, playback_status, metrics | 기본 메모리. 동의 시 저장 |
| `Attempt` | exercise_id, attempt_index, 원본/수정 전사, result_version | 기본 메모리. 동의 시 저장 |
| `Feedback` | 근거·제안·상태·모델/프롬프트 revision | 해당 전사 revision과 함께 저장 |
| `Job` | job_id, state, idempotency_key, ttl, error_code | 재시작 상태 복구용 최소 메타데이터. 오디오 payload는 메모리 |
| `ModelManifest` | model_id, revision, hash, runtime, license, benchmark_id | 설치·진단 정보 |

`session_id + turn_index`와 제출 idempotency key에 중복 방지 제약을 둔다. 완료 결과 저장과 작업 상태 전환은 한 트랜잭션으로 처리한다. 각 워커가 자기 SQLite 복사본을 만드는 대신 게이트웨이가 쓰기를 관리한다.

### 13.5 발음 결과 (v0.2)

녹음형 시도 결과(`GET /api/attempts/{id}/result`)에 `pronunciation` 객체를 추가한다. 형식 예시이며 실제 분석 결과가 아니다.

```json
{
  "pronunciation_score": null,
  "pronunciation_status": "timing_only",
  "pronunciation": {
    "status": "timing_only",
    "words": [
      {"i": 0, "word": "Yesterday", "start_ms": 120, "end_ms": 610, "gap_before_ms": 0, "band": null}
    ],
    "prosody": {"learner": {"hop_ms": 10, "f0_hz": [0, 182.4], "per_word": []}, "model": null},
    "calibration_version": null,
    "model_revisions": {"aligner": "<revision>"},
    "note_ko": "단어 위치와 억양 곡선만 보여 줍니다. 발음을 채점하지 않습니다."
  }
}
```

- 필드 목록·상태 전이·워커 API는 `contracts/PROTOCOL.md` §12가 기준이다.
- 발음 분석은 작업 상태 `analyzing` 안에서 수행하며 새 작업 상태를 만들지 않는다. 발음 워커 실패는 작업 실패가 아니다(`status: "unavailable"`, 나머지 결과 유지).
- 전사를 수정해도 과거 음성의 단어 위치를 새 전사로 다시 계산하지 않는다(§13.3). 발음 결과는 원래 revision에 묶인다.
- 기록 저장에 동의한 경우에도 억양 곡선·음소 후보는 저장하지 않고, 단어 위치와 등급만 텍스트 이력과 함께 저장할 수 있다. 음성은 어떤 경우에도 저장하지 않는다.

## 14. 로컬 실행·자원·배포

### 14.1 지원 프로필

아래는 장비 구매 권장이나 모델의 공식 최소 사양이 아니라 **개발 검증 범위**다.

| 프로필 | 목표 | 지원 판정 |
|---|---|---|
| 기준 GPU | Linux x86_64, NVIDIA GPU 16 GB VRAM, RAM 32 GB를 최초 검증 장비 후보로 설정 | 두 모드·끼어들기·오프라인·지연 테스트를 통과하면 지원 |
| 제한 메모리 | 더 작은 VRAM 또는 RAM | LLM CPU offload·짧은 문맥·순차 처리 검증. 실시간 자동 보장 없음 |
| CPU 전용 | 동일 모델의 호환 런타임을 별도 검증 | 먼저 녹음형 실행을 확인. 실행 자체와 실시간 사용성을 구분 |
| Apple Silicon | 별도 런타임/변환 검증 | vLLM-Metal 등 런타임의 존재만으로 이 ASR/TTS 조합의 지원을 선언하지 않음 |
| Windows | WSL 기반 검증을 우선 검토 | 실제 마이크·브라우저·GPU 연결까지 통과해야 지원 |

vLLM의 현재 설치 문서는 Linux 및 GPU별 설치 경로, Windows의 WSL 안내, Apple Silicon용 별도 경로를 제공한다. 특정 런타임의 설치 가능 여부와 이 모델 조합의 호환성은 따로 확인한다. [S10]

기준 개발 환경의 저장 공간은 모델·환경·컨테이너를 포함해 여유 50 GB를 **초기 작업 예산**으로 잡고 실제 설치 크기를 기록한다. 로컬 실행은 외부 API 사용료를 없애지만 장비·전력·유지보수 비용까지 없애는 것은 아니다.

### 14.2 자원 정책

- 같은 모델을 웹 워커 수만큼 중복 적재하지 않는다. 게이트웨이와 모델 프로세스 수를 독립 설정한다.
- ASR·TTS·LLM의 상주 메모리, KV cache, 컴파일·예열 증가분을 함께 측정한다. 파라미터 개수만 더해 VRAM 요구량을 단정하지 않는다.
- ASR의 vLLM 메모리 예약을 전체 GPU 독점 값으로 두지 않는다. 다른 워커를 적재한 상태로 예산을 검증한다.
- 실시간 세션 중 상세 피드백·단어 정렬·비실시간 작업을 경쟁 실행하지 않는 것을 기본으로 한다. 정렬 모델은 필요할 때만 적재한다.
- LLM 생성과 TTS 합성의 겹침은 합성 품질·응답 지연·메모리를 측정한 뒤 허용한다. 취소된 작업은 즉시 논리적으로 차단하고 실제 GPU 작업 해제도 추적한다.
- 메모리 부족 시 새 세션을 거절하거나 사용자 동의로 녹음형으로 전환한다. 다른 모델이나 클라우드로 몰래 바꾸지 않는다.

### 14.3 설치·실행 산출물

다음 명령은 구현할 로컬 런처의 계약이다. 현재 제공된 실행 코드가 아니다.

| 명령 | 동작 |
|---|---|
| `./app setup` | 명시적 동의를 받아 필요한 모델·런타임·음성 자산 설치, 해시 확인 |
| `./app doctor` | 장비·모델·의존성·포트·음성 경로·오프라인 준비 점검 |
| `./app start` | 로컬 워커 예열 후 웹앱 시작. 준비 전 학습 시작 차단 |
| `./app stop` | 진행 작업 취소, 음성 버퍼 제거, 워커 종료 |
| `./app benchmark` | 합의된 데이터셋으로 지연·자원·품질 측정 결과 생성 |

최초 설치 후 실행 과정에서 모델을 자동 다운로드하지 않는다. 필요한 파일이 없으면 설치 안내와 함께 실패한다. `latest` 태그에 의존한 자동 업데이트는 하지 않는다. 업데이트는 이전 잠금 파일·모델로 되돌릴 수 있어야 한다.

## 15. 성능·품질 수용 기준

**아래 수치는 출시 전 검증할 목표다. 이번 문서 작성 과정에서 측정된 결과가 아니다.** 기준 장비·모델 revision·정밀도·동시 실행 조건과 함께 관리한다.

### 15.1 성능 목표

| 지표 | 초기 목표 | 측정 정의 |
|---|---|---|
| 실시간 응답 시작 | p50 ≤ 2초, p95 ≤ 4초 | 사용자 마지막 음성 샘플 → AI 첫 유효 음성의 실제 재생. 종료 침묵 포함 |
| 첫 임시 전사 | p95 ≤ 3초 | 사용자 발화 시작 → 첫 유효 임시 자막 |
| 자동 끼어들기 | p95 ≤ 350 ms | 실제 사용자 발화 시작 → AI 음성 정지 |
| 중지 버튼 | p95 ≤ 150 ms | 클릭 → 클라이언트 음성 정지 |
| 연속 TTS 생성 | 응답별 RTF p95 ≤ 0.8 | 생성 벽시계 시간 ÷ 생성 음성 길이. 1보다 작아야 음성 길이보다 빠른 생성 |
| 녹음형 전사 | 30초 입력의 p95 ≤ 15초 | 제출 완료 → 전체 전사 표시 |
| 녹음형 전체 결과 | 30초 입력 p95 ≤ 25초, 120초 입력 p95 ≤ 60초 | 제출 완료 → 피드백과 첫 모범 음성 준비. 대기열 시간 포함 |
| 안정성 | 60분 연속 테스트에서 OOM·프로세스 비정상 종료 0건 | 취소·재시도·모드 전환 포함 |
| 메모리 회수 | 동일 길이 세션 10회 후 안정 상태 메모리 증가 ≤ 10% | 초기 예열·캐시 증가를 제외하고 비교 |

준비 전 cold start는 별도로 기록하고 위 warm 지연 지표에서 제외한다. 시작 화면은 실제 준비 상태를 보여 주며, 예열 중인 상태를 정상 대화로 집계하지 않는다.

`RTF < 1`만으로 낮은 첫 응답 지연이나 끊김 없는 재생을 보장하지 않는다. 청크 간 재생 공백, 첫 음성 지연, 취소 지연도 별도로 측정한다. 서버의 첫 byte 전송 시점을 실제 사용자 청취 시점으로 대신하지 않는다.

### 15.2 품질 목표

| 항목 | 초기 릴리스 기준 |
|---|---|
| 영어 전사 | 별도 확보한 학습자 평가셋에서 조용한 환경 WER ≤ 20%를 검증 목표로 설정. 난이도·억양별 결과도 공개 |
| 시나리오 유지 | 100개 scripted 대화 케이스 중 95개 이상에서 역할·명시된 상황 사실 유지 |
| 텍스트 교정 | 사람이 검수한 최소 100개 피드백에서 잘못된 교정 ≤ 5%. 미확인 사례를 정답으로 간주하지 않음 |
| 근거 연결 | 사용자 문장을 인용하는 피드백은 해당 전사 revision의 실제 구간과 100% 연결 |
| TTS 핵심 어휘 | 검수 예문에서 가격·날짜·부정어 등 의미를 바꾸는 읽기 오류 0건. 일반 문장은 청취 검수로 별도 기록 |
| 발음 평가 정직성 | 채점 모듈이 없을 때 음소 점수·총 발음 점수·원어민 유사도 표시 0건. **(v0.2)** 기본 설정(`timing_only`)에서 발음 등급·판정 표시 0건, 어떤 설정에서도 발음 관련 숫자 점수 표시 0건, 한국인 학습자 정확도 주장 0건 |
| 취소 일관성 | 100회 끼어들기 테스트에서 취소된 응답의 후속 재생 0건 |
| 중복 방지 | 재전송·중복 클릭으로 턴·시도·AI 응답이 중복 생성되는 사례 0건 |

### 15.3 벤치마크 방식

최소 10명의 동의된 영어 학습자 또는 적절히 허가된 평가 음성으로 200개 발화를 확보한다. 고정 평가셋과 튜닝셋을 분리하고, 조용한 환경·망설임·잡음·짧은 답변·긴 답변을 포함한다. 제품에서 수집한 음성을 동의 없이 테스트 데이터로 전용하지 않는다.

전체 스택을 켠 상태에서 warm 대화 턴을 200회 이상 측정한다. GPU 이름·VRAM·CPU·RAM·OS·모델 hash·정밀도·런타임·컨텍스트·음성 자산·브라우저·오디오 장치를 결과와 함께 기록한다. 컴포넌트 단독 수치로 전체 시스템 통과를 선언하지 않는다.

브라우저의 동일한 monotonic clock으로 캡처·재생 이벤트를 기록하고, 일부 케이스는 loopback 녹음으로 실제 정지·첫 소리 시점을 확인한다. 모델 업데이트·양자화 변경·런타임 교체 후에는 같은 세트로 재검증한다.

## 16. 개인정보·보안·오프라인 정책

| 대상 | 기본 정책 |
|---|---|
| 마이크 원본 | 디스크·DB·object storage에 저장하지 않음. 필요한 구간만 제한된 메모리에 보유 |
| 실시간 음성 | 현재 발화와 즉시 처리용 버퍼만 보유. 지표 계산·필요한 처리 후 해제 |
| 녹음형 음성 | 서버는 결과/취소/실패 시 해제. 브라우저의 미리 듣기는 최대 5분 또는 화면 종료까지 |
| 재시작 | 음성 payload는 복구하지 않음. 진행 작업은 실패/만료로 정리 |
| 전사·피드백 | 기본은 세션 메모리. 명시적으로 선택한 경우에만 로컬 이력 저장 |
| 미저장 세션 | 종료 후 요약을 최대 15분 표시하고 만료. 사용자가 닫거나 삭제하면 즉시 정리 |
| TTS 출력 | 사용자 대화에서 생성된 음성도 기본은 메모리만 사용 |
| 기준 음성·예문 | 사용 권리가 확인된 서비스 자산은 설치 파일로 보관 가능 |
| 로그 | 지연·길이·상태·오류 코드만 기록. 음성·전사·TTS 문장·프롬프트·비밀값 제외 |
| 외부 통신 | 실행 중 외부 추론·분석·텔레메트리·CDN·모델 다운로드 없음 |

오디오 업로드 처리에는 메모리 한도를 적용하며, 웹 프레임워크가 파일을 임시 디스크에 자동 spool하지 않도록 구성·시험한다. 모델 의존성의 stdout/stderr와 TTS 텍스트 로그도 검사한다. CosyVoice 코드에는 합성 텍스트를 기록하는 경로가 있으므로 애플리케이션 로그만 끈 것으로 충분하다고 보지 않는다. [S11]

기본 서비스는 loopback에만 바인딩한다. Host/Origin allowlist, 로컬 세션 인증, 변경 요청의 CSRF 방어, WebSocket 인증, 입력 크기 제한을 적용한다. 인증 토큰을 URL query나 로그에 남기지 않는다. LAN 접근은 기본 비활성화한다.

모델 로딩은 검수된 코드·해시가 고정된 파일만 허용한다. 사용자가 임의 모델 경로나 스크립트를 API로 실행하게 하지 않는다. 오프라인 모드에서 외부 연결이 발생하면 테스트 실패로 간주한다.

앱이 오디오를 파일로 쓰지 않는 것과 운영체제 swap·crash dump까지 흔적이 없다는 보장은 다르다. 엄격한 환경에는 암호화된 저장장치·swap·dump 정책을 별도 적용한다. 이력 삭제도 앱의 논리적 삭제와 저장매체의 포렌식 불가능성을 혼동하지 않는다.

## 17. 오류와 복구

| 상황 | 사용자에게 보이는 동작 | 내부 처리 |
|---|---|---|
| 마이크 거부·없음 | 권한/장치 안내, 녹음 시작 차단 | 성공 상태·빈 제출 생성 금지 |
| 무음·입력 부족 | 다시 말하기 안내 | LLM 호출·교정·실패 점수 생성 안 함 |
| 잡음·전사 불안정 | 인식 문장 확인 또는 재녹음 | 교정 `needs_confirmation` |
| ASR 실패 | 재시도 또는 녹음형 전환 안내 | 해당 턴에서 추측 답변 생성 금지 |
| LLM 실패 | 대화 재시도 버튼, 전사는 보존 | 응답 idempotency 유지 |
| TTS 실패 | 텍스트 답변 + 음성 재시도 | 새 음성 response ID/epoch 사용 |
| GPU OOM | 현재 모드 제한과 복구 안내 | 작업 정리·readiness 재점검. 무한 재시도 금지 |
| 워커 종료 | 실패한 단계와 재시도 안내 | 정상 워커까지 불필요하게 재시작하지 않음 |
| 연결 종료 | 재생·마이크 정지, 재연결 상태 표시 | 미완료 출력 취소, 중복 commit 방지 |
| 작업/음성 만료 | 재녹음 필요 표시 | 없는 파일을 복원하려 하지 않음 |
| 저장 공간 부족 | 이력 저장 실패를 알림 | 메모리 연습 가능 여부를 따로 판정 |
| 모델 파일 누락 | 설치 안내 | 실시간 외부 다운로드로 숨기지 않음 |

초기 재시도는 일시적 추론 실패에 한해 최대 1회로 제한한다. 취소·형식 오류·권한 오류·만료는 자동 재시도하지 않는다. 텍스트 결과가 생성되었는데 음성만 실패한 경우 전체 학습을 실패로 덮어쓰지 않는다.

보안·오디오 누출·중복 생성·취소 후 재생·근거 없는 발음 점수는 **출시 차단 결함**이다. 실시간 목표를 충족하지 못하면 녹음형은 개발 검증에 사용할 수 있지만, 두 모드를 지원하는 MVP 출시가 완료됐다고 표시하지 않는다.

## 19. 구현 단계와 산출물

| 단계 | 내용 | 다음 단계 진입 조건 |
|---|---|---|
| M0 — 기술 검증 | ASR streaming/offline, CosyVoice 영어 streaming, 로컬 LLM, 전체 상주 메모리, 취소 가능성 확인 | 실제 음성 입출력 증거, 잠금 정보, 실행 프로필별 지원/미지원 기록 |
| M1 — 녹음형 수직 구현 | 녹음·제출·실제 전사·피드백·모범 음성·재시도·원본 미저장 | NR 요구사항과 관련 AT 테스트 통과 |
| M2 — 실시간 수직 구현 | WebSocket, VAD, 임시 자막, 응답 분절, 스트리밍 재생, 끼어들기 | RT 요구사항과 취소·에코·중복 방지 테스트 통과 |
| M3 — MVP 통합 | 시나리오 4개, 학습 보조, 선택적 이력, 설치·진단, 오프라인·품질 검증 | 두 모드 모두 기준 장비에서 출시 기준 통과 |
| 후속 | 단어 정렬, 추가 시나리오, 장비 프로필 확대, 보정된 음소 평가 | 별도 요구사항·데이터 검증. MVP 점수로 소급 적용하지 않음. **(v0.2)** 발음 분석은 §8.4 단계와 `docs/TRIAGE.md` PA 순서를 따른다 |

### 권장 저장소 구조

아래는 새 프로젝트의 제안 구조다. 실제 기존 경로가 있다는 의미는 아니다.

```text
apps/web/                 # 학습 UI, 캡처, 재생, 상태 표시
services/gateway/         # HTTP/WS, 인증, 세션, 큐, DB
workers/asr/              # Qwen 어댑터, 스트리밍 상태
workers/tts/              # CosyVoice 어댑터, 음성 자산, 취소
workers/feedback/         # 지표 계산, 로컬 LLM 피드백 계약
config/llm/               # llama.cpp 설정, 양자화 모델 manifest
content/scenarios/        # 시나리오와 검수된 표현
content/voices/           # 허가된 기준 음성 및 출처
contracts/                # 이벤트·요청·결과 스키마
tests/unit/               # 상태·변환·분절·멱등성
tests/integration/        # 실제 모델별·전체 스택 테스트
tests/e2e/                # 브라우저·오디오·오프라인 테스트
benchmarks/               # 허가된 평가셋 manifest, 측정 결과
scripts/                  # setup, doctor, start, stop, benchmark
models.lock.json          # 모델·변환·해시·라이선스
```

개발 완료 산출물은 실행 가능한 서비스, 잠금 파일, 로컬 실행 설명서, 장비별 실측 보고서, 테스트 결과, 데이터 보존 검사 결과다. 모델 API가 연결된 것처럼 보이는 mock UI만으로 완료하지 않는다.

## 20. 핵심 위험과 최종 결정

| 위험 | 대응 | 결정 시점 |
|---|---|---|
| 작은 모델이어도 전체 스택 메모리가 큼 | 모든 워커를 동시에 적재하고 예약 메모리 측정 | M0 |
| ASR/TTS 런타임 의존성 충돌 | 환경 분리, 버전 고정, 모델별 smoke test | M0 |
| 취소가 오디오만 멈추고 계산은 계속됨 | 출력 무효화와 워커 취소를 분리 검증, 잔여 계산 시간 계측 | M0~M2 |
| 스피커 에코로 스스로 말 끊기 | 헤드셋·AEC·에코 테스트, 실패 시 명시적 보조 모드 | M2 |
| 학습자 억양을 교정 오류로 오인 | 전사 확인, 피드백 근거, 사람 검수, 발음 점수 비활성화 | M1~M3 |
| LLM이 문법·상황 정보를 잘못 판단 | 시나리오 사실 고정, 근거 인용, schema 검증, 보류 정책 | M1~M3 |
| 특정 단어의 TTS 발음 오류 | 검수된 예문·CMU 사전·회귀 청취 테스트 | M0~M3 |
| 오프라인 앱의 숨은 네트워크·로그 | 네트워크 차단 테스트, 의존성 로그·캐시 검사 | M3 |

**확정할 제품 방향:** `Qwen3-ASR 0.6B + CosyVoice3 0.5B`를 유지하고, 로컬 대화 LLM을 더해 **실시간 역할극과 녹음형 연습을 모두 제공한다.** 복잡한 음소 채점보다 대화 안정성·좋은 모범 음성·근거 있는 교정·다시 말하기를 먼저 완성한다.

**출시 전 남은 확인:** 사용자 실제 장비, 모델/런타임 잠금 revision, 영어 음성 자산의 권리·품질, 전체 스택 메모리·지연, 학습자 평가셋 결과. 미측정 수치를 성능 보장으로 바꾸지 않는다.
