# 발음 분석: 무엇을 보여 주고 무엇을 판단하지 않는가

작성일 2026-09-28 (PRD v0.2 §8.4, `contracts/PROTOCOL.md` §12, `docs/TRIAGE.md` PA-7). 이 문서는 학습자와 검토자를 위한 설명이고, 정확한 필드와 규칙은 PROTOCOL이 기준입니다.

## 한 줄 요약

이 앱은 **발음을 채점하지 않습니다.** 기본 설정에서는 녹음에서 각 단어를 어디서 말했는지, 목소리 높낮이(억양)가 어떻게 움직였는지를 보여 주고, 내 발음과 모범 음성을 단어별로 나란히 들어 볼 수 있게 합니다. "맞다/틀리다" 판정은 실험 기능으로만 있고 기본으로 꺼져 있습니다.

## 1. 보여 주는 것과 판단하지 않는 것

| 보여 주는 것 (기본) | 뜻 | 판단하지 않는 것 |
|---|---|---|
| 단어 위치 | 녹음에서 각 단어가 시작하고 끝난 시각, 단어 길이, 단어 앞 쉼 | 단어 위치를 찾았다고 발음이 맞았다는 뜻이 아닙니다. 못 찾았다고 틀렸다는 뜻도 아닙니다 |
| 단어별 비교 재생 | 단어를 누르면 내 녹음의 그 구간과 모범 음성의 같은 단어를 이어서 들려줍니다 | 두 소리가 얼마나 비슷한지 점수를 매기지 않습니다 |
| 억양 곡선 | 목소리 높낮이 변화를 그래프로 보여 줍니다. 모범 음성 곡선이 있으면 함께 보여 줍니다 | 모범 음성과 다르다고 감점하거나 "억양이 틀렸다"고 하지 않습니다. 자연스러운 억양은 여러 가지입니다 |

어떤 설정에서도 하지 않는 것:

- 0~100 같은 발음 점수, 백분율, "원어민과 몇 % 비슷함" 표시 (`pronunciation_score`는 항상 비어 있음)
- 한국인 학습자에 대해 "정확하다"는 주장
- AI 대화 모델(LLM)이 글자만 보고 "r 발음이 틀렸어요"처럼 말하는 것. 발음 관련 표시는 소리를 직접 분석한 결과에서만 나옵니다
- 클라우드 발음 서비스로 녹음 보내기

"다르게 인식된 부분"(v0.1부터 있던 기능)은 음성 인식 결과와 목표 문장을 비교한 것일 뿐, 발음 판정이 아닙니다. 음성 인식은 문맥으로 단어를 보정하는 경향이 있어서 실제 발음 실수를 놓칠 수 있습니다.

## 2. 실험 기능: 단어 등급

개발·검증용 설정(`VR_PRON_EXPERIMENTAL=1`)과 보정 파일이 **둘 다** 있을 때만 켜집니다. 켜지면:

- 단어마다 세 등급 중 하나를 보여 줍니다: 좋음(`good`) / 확인해 보세요(`check`) / 연습해 보세요(`practice`). 색과 함께 글자·아이콘으로도 표시하고, 숫자는 보여 주지 않습니다.
- "이렇게 들렸을 가능성이 있어요"라는 소리 후보(IPA 기호)를 보여 줄 수 있습니다. 확률 숫자는 보여 주지 않습니다.
- 항상 "실험 기능이며 한국인 학습자로 검증되지 않았다"는 안내가 함께 나옵니다.
- 자유 답변처럼 정해진 문장이 없는 연습은 음성 인식 결과를 기준 문장으로 씁니다. 인식이 틀리면 멀쩡한 발음이 틀린 것처럼 보일 수 있으므로, 학습자가 인식 문장을 확인하기 전에는 판정을 "확인 필요"로 보류합니다.

**왜 기본으로 꺼져 있나요?** 기본으로 켜려면 동의를 받은 한국인 학습자 녹음에 사람 평가자 2명 이상이 점수를 매긴 평가셋이 있어야 하고, 앱의 판단이 사람 평가와 충분히 일치해야 합니다(음소 수준 상관 0.55 이상, 단어 수준 0.5 이상). 2026-09-28 현재 이 평가셋이 없으므로 기준을 확인할 방법이 없고, 그래서 꺼져 있습니다. 참고로 최고 수준의 공개 시스템도 사람 평가와의 상관이 0.6~0.75 정도라서, 작은 차이는 의미가 없습니다. 등급만 쓰고 숫자를 쓰지 않는 이유입니다.

## 3. 처리 과정

모든 처리는 이 컴퓨터 안에서 하고, 녹음형 연습에서만 동작합니다. 실시간 회화 중에는 발음 분석을 하지 않습니다.

```text
녹음 제출
 → 음성 인식(전사)                           기존과 같음
 → 발음 워커 (127.0.0.1:8714, 선택 설치)
     단어 위치 찾기   Qwen3-ForcedAligner-0.6B
     억양 곡선        pyworld (Harvest, 10 ms 간격)
     [실험] 소리 후보·등급   wav2vec2-lv-60-espeak-cv-ft + 보정 파일
 → 모범 음성이 같은 문장이면 모범 음성에도 단어 위치·억양 곡선 계산
 → 결과 화면: 단어 위치, 비교 재생, 억양 곡선 (실험 설정이면 등급)
```

- 기준 문장: 문장 읽기·따라 말하기·다시 말하기는 제시 문장, 자유 답변·턴제 역할극은 음성 인식 결과를 씁니다.
- 발음 워커가 없거나, 실패하거나, 시간이 너무 걸리면 "이번 녹음은 발음 분석을 하지 못했어요"라고 표시하고 나머지 결과(전사, 표현 피드백, 모범 음성)는 그대로 보여 줍니다.
- 녹음은 분석이 끝나면 서버 메모리에서 지웁니다. 비교 재생의 "내 발음"은 브라우저가 가지고 있는 녹음 사본을 씁니다.
- 기록 저장을 켠 경우에도 억양 곡선, 소리 후보, 음성은 저장하지 않습니다. 단어 위치와 (실험 설정이면) 등급만 텍스트 기록과 함께 저장할 수 있습니다.

## 4. 보정 상태

| 항목 | 상태 (2026-09-28) |
|---|---|
| 한국인 학습자 평가셋 (PA-0) | 없음. 녹음 동의, 평가 가이드, 평가자 모집이 필요합니다 |
| 공개 벤치마크 speechocean762 결과 (PA-2) | 아직 측정하지 않았습니다 |
| 보정 파일 | 없음. 따라서 실험 설정을 켜도 등급은 나오지 않습니다 |
| 단어 위치 정확도 | 아직 측정하지 않았습니다 |
| 억양 곡선이 한국인 학습자에게 도움이 되는지 | 아직 검토하지 않았습니다 (PA-5) |

측정 결과가 생기면 이 표와 `benchmarks/` 아래 리포트를 함께 갱신합니다. 측정하지 않은 수치를 적지 않습니다.

## 5. 한계와 편향

- **악센트 편향.** 공개 보정 데이터 speechocean762는 중국어가 모국어인 화자만 포함합니다. 이 데이터로 맞춘 기준은 한국어 화자의 흔한 발음 특징(예: r/l, f/p, v/b, th, 모음 길이)을 다르게 판단할 수 있습니다. 그래서 실험 기능으로만 쓰고 정확도를 주장하지 않습니다.
- **음소 인식 모델의 기준.** wav2vec2 음소 모델은 여러 언어의 낭독 음성으로 학습됐고, 특정 영어 억양(미국식·영국식 등)을 기준으로 삼는 경향이 있을 수 있습니다. 다른 억양이 틀린 것은 아닙니다.
- **음성 인식 보정.** 자유 발화에서는 음성 인식 결과를 기준으로 삼기 때문에, 인식 오류가 발음 오류처럼 보일 수 있습니다.
- **녹음 환경.** 잡음, 작은 목소리, 끊긴 녹음에서는 단어 위치와 억양 곡선이 부정확해집니다. 이런 경우 분석을 보류하거나 비가용으로 표시하고, 학습자 실력이 낮은 것으로 기록하지 않습니다.
- **억양은 정답이 하나가 아닙니다.** 모범 음성의 억양은 여러 자연스러운 방식 중 하나입니다.

## 6. 사용하는 모델과 라이선스

| 구성 요소 | 용도 | 라이선스 | 출처 |
|---|---|---|---|
| Qwen3-ForcedAligner-0.6B | 단어 위치 찾기 | Apache-2.0 | https://huggingface.co/Qwen/Qwen3-ForcedAligner-0.6B |
| wav2vec2-lv-60-espeak-cv-ft | 소리(음소) 후보, 실험용 | Apache-2.0 | https://huggingface.co/facebook/wav2vec2-lv-60-espeak-cv-ft |
| pyworld (WORLD) | 억양 곡선(피치) | MIT | https://github.com/JeremyCCHsu/Python-Wrapper-for-World-Vocoder |

라이선스는 2026-09-28에 Hugging Face·GitHub 저장소 표기로 확인했습니다. 모델 revision과 파일 해시는 `models.lock.json`에 고정합니다.

쓰지 않는 것:

- **Parselmouth(Praat)**: GPL-3.0이라 배포 조건이 달라지므로 피합니다. 피치 추출은 pyworld로 대신합니다.
- **espeak-ng, phonemizer**: 둘 다 GPL-3.0입니다. 문장을 기대 발음 기호로 바꾸는 단계(G2P)에 흔히 쓰이지만, 라이선스 결정을 기록하기 전에는 추가하지 않습니다. 대안(CMUdict 기반 등)은 PA-2에서 라이선스를 확인한 뒤 고릅니다.
- **CTC-based-GOP 저장소**: 라이선스가 명시되지 않아 코드를 가져오지 않습니다. 논문의 방법만 참고합니다.
- **클라우드 발음 API(Azure 등)**: 로컬·오프라인 원칙 때문에 쓰지 않습니다.
